# 赌坊买下流程完善 + 万次开仓平均灵气模拟 — 规格

## 背景（已确认的代码事实）

- 文件：`d:\TFSSS\TaFangSSS\Assets\Scripts\Window\赌坊\赌坊界面.cs`（唯一要改的文件）
- 灵气货币 = `PlayerData.S.PropListDic[PropType.灵魂]`
- 单件藏品的灵气价值 = `赌坊Config.藏品价格Dic[藏品Type]`（藏品仓库item/藏品百科item 均以此显示"价格（灵气）"）
- 仓库价格 = `计算价格()` = `赌坊配置.首仓价格 × 轮数价格倍数[轮数]`（第 545-557 行）
- `买下()`（第 650-682 行）现状：检查灵气 → 扣灵气 → 藏品入 `藏品仓库Dic` → `已买下 = true` → 渲染/存档。**缺少"加回仓内藏品灵气总和"**。
- `Start()`（第 59-94 行）绑定按钮；第 12-13 行已有用户新加的 `开仓1000次Button` / `开仓1000次平均灵气` 字段，尚未绑定。
- 仓库真实生成流程 `生成仓库()`（第 278-325 行）：重置存档 → `藏品背包.开始生成(0)` → while 循环 `按概率抽取品质()` + `取品质候选()` + `尝试放置()` + `记录藏品()` → `补满空格()`。
- `随机占格背包` 的 `开始生成/尝试放置/单格放置/已填满` 是**纯逻辑 API**；只有 `创建藏品()` 才实例化 UI。不调用 `创建藏品` 即可零渲染模拟。
  - 注意：`开始生成()` 内部 `清除已有物品()` 会销毁当前已渲染的藏品物体，模拟结束后需调用 `渲染藏品()` 从存档恢复视觉（存档未被模拟改动，视觉完全还原）。
- 概率/候选/尺寸辅助方法 `按概率抽取品质()`、`取品质候选()`、`取单格藏品()`、`取藏品尺寸()` 均为本类私有方法，模拟方法写在本类内可直接复用，保证"真实"。

## 目标

1. **买下加灵气**：`买下()` 扣掉仓库价格后，把仓内所有藏品的 `藏品价格Dic` 价值之和加回 `PropListDic[PropType.灵魂]`。
2. **万次模拟**：点 `开仓1000次Button` 执行 10000 次真实逻辑的模拟开仓（不扣灵气、不写存档、不渲染、不更换真实仓库），把每仓藏品灵气总和的平均值格式化显示到 `开仓1000次平均灵气`。

## 非目标

- 不改 `赌坊Config.cs`、`随机占格背包.cs`、`PlayerData.cs` 及任何数据结构。
- 不改提示文案风格之外的任何交互流程。
- 不做协程/分帧（调试按钮，主线程同步执行即可）。

### 修改 3：`买下()` 之后新增 `调试开仓10000次()`

逻辑完全复刻 `生成仓库()` + `补满空格()`，差异仅在于：藏品收集到本地 `List<藏品Type>`，不写 `PlayerData.S.赌坊存档`：

```csharp
private void 调试开仓10000次()
{
    if (藏品背包 == null) return;

    const int 次数 = 10000;
    int 行 = 取行数();
    int 列 = 取列数();
    藏品背包.行数 = 行;
    藏品背包.列数 = 列;

    double 总灵气 = 0;
    for (int n = 0; n < 次数; n++)
    {
        藏品背包.开始生成(0);
        List<藏品Type> 本仓 = new List<藏品Type>();

        int 连续失败 = 0;
        while (!藏品背包.已填满 && 连续失败 < 400)
        {
            QualityType 品质 = 按概率抽取品质();
            List<藏品Type> 候选 = 取品质候选(品质);
            bool 已放置 = false;

            if (候选.Count > 0)
            {
                int 尝试次数 = Mathf.Min(候选.Count, 8);
                for (int i = 0; i < 尝试次数; i++)
                {
                    藏品Type type = 候选[Random.Range(0, 候选.Count)];
                    Vector2Int 尺寸 = 取藏品尺寸(type);
                    if (藏品背包.尝试放置(尺寸, out int _, out int _))
                    {
                        本仓.Add(type);
                        已放置 = true;
                        break;
                    }
                }
            }

            连续失败 = 已放置 ? 0 : 连续失败 + 1;
        }

        for (int y = 0; y < 行 && !藏品背包.已填满; y++)
        {
            for (int x = 0; x < 列; x++)
            {
                if (藏品背包.已填满) break;
                藏品Type type = 取单格藏品(按概率抽取品质());
                if (type == 藏品Type.None) continue;
                if (!藏品背包.单格放置(x, y)) continue;
                本仓.Add(type);
            }
        }

        float 本仓灵气 = 0;
        foreach (藏品Type type in 本仓)
        {
            if (赌坊Config.藏品价格Dic.TryGetValue(type, out float 价格)) 本仓灵气 += 价格;
        }
        总灵气 += 本仓灵气;
    }

    float 平均 = (float)(总灵气 / 次数);
    if (开仓1000次平均灵气 != null) 开仓1000次平均灵气.text = PlayerData.S.格式化数字(平均);

    // 模拟重置了占用表并销毁了已渲染藏品，按未改动的存档重新渲染恢复界面
    渲染藏品();
}
```

要点与决策：
- **不改存档**：全程不触碰 `PlayerData.S.赌坊存档.藏品列表`，灵气余额不变。
- **不渲染**：不调用 `创建藏品()`，10000 次循环零 UI 分配，主线程一次跑完。
- **真实性**：抽取品质、候选、尺寸、占格、补空格全部走与真实开仓相同的代码路径与随机分布。
- **溢出安全**：累加用 `double`。
- **界面恢复**：结束后仅 `渲染藏品()`（存档未变，视觉与点击前一致）；无需重新 `生成仓库()`——那才是"刷新仓库"，用户明确不要。
